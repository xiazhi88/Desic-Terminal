# 内置专家重构规划（2026-09-19）

董事会三条决定：
1. **不固定"谁并行谁串行"** —— 并行/串行由**主 Agent**自己决定（用户可能自定义专家、可能取消勾选某个专家）。
2. **不设轮次上限**（去掉 `maxIterations` 类限制）。
3. **删除原 8 个内置专家**，替换为新的一组。

本文件是规划与风险预案，不含实现细节最终值。

---

## 一、新的默认专家集（按"流程角色"划分，而不是按市场名词）

| 角色 | 职责 | 依赖 | 建议工具面（点名时 `scopes`） | 输出契约 |
| --- | --- | --- | --- | --- |
| **数据汇总** `desic-data-digest` | 一次把行情、衍生品、聪明钱、新闻、历史数据读齐，产出**结构化摘要** | 无（可与其他无依赖角色并行） | market + derivatives + intelligence（+ history / radar 视需要） | **摘要**：证据清单（工具/时间戳/记录 ID）、关键数值、时效、缺口 |
| **账户与持仓** `desic-account-state` | 持仓、普通/算法挂单、止损止盈状态、保证金率（含口径）、可用余量 | 无 | account + 基础行情（`requiresAccount: true`） | **状态清单** + 风险标记（无观点的纯事实） |
| **分析/决策候选** `desic-decision-proposal` | 基于摘要 + 账户状态，产出**候选决策**（方向/入场/仓位/失效条件/风险回报） | 需要前两者产出 | 基础行情 + history（少取证，主要推理） | **决策候选**：结论、用到的证据 ID、会改变结论的条件 |
| **反方审查** `desic-contrarian-review` | 尝试**推翻**候选决策 | 需要候选决策 | 最小面（history + intelligence 定点核对） | **反驳/证伪**：逐条反驳、可检验依据、或明确"无法推翻"、或"需补什么证据" |

- 原 8 个：**删除内置**（内容、`BUILTIN_AGENT_SPECS`、指纹基线与测试同步）。用户已启用旧 ID 的处理见 §五 迁移。
- 用户可自定义、可取消勾选 —— **所有下游必须对"缺少某个角色"具备降级能力**（§三）。

---

## 二、并行/串行交给主 Agent：怎么保证它做对

**不新增机制**：现有"一次 `consult_experts` 调用必须等整批返回"天然构成阶段边界，主 Agent 用**多次调用**表达任意管线。

写进编排 Skill 的**判断规则**（不是固定管线）：

1. 无依赖、只读、不共享外部资源（账户状态、同一限频上游） → 可同批并行
2. 需要读取别人本轮产出的报告/结论 → 串行（用另一次调用）
3. 明确写出"哪些角色天然依赖"：分析依赖数据/账户；反方依赖候选决策；任何复核依赖被复核对象
4. 明确禁止"按名单全派"：按本轮需要派，能自己便宜查清的自己查
5. 反方最多一轮：若提出需补证，主 Agent 决定是否补，补后**不再重复反方**

**软校验（不做硬管线，但可事后审计）**：run 记录保存每位专家的 `startedAt/endedAt` 与批次归属 → 复盘可发现"分析专家比数据专家先启动"这类明显违规。

## 三、用户自定义/缺角色时的降级矩阵（必须实现的行为）

| 缺失情形 | 降级行为 |
| --- | --- |
| 未启用"数据汇总" | 主 Agent **自己取证**，并在报告里说明"本轮未派数据专家" |
| 未启用"账户与持仓" | 主 Agent 自行读账户（需绑账户）；若未绑账户 → 明确写出"账户证据缺失" |
| 未启用"分析/决策候选" | 主 Agent 自己分析（回到 v3 现状） |
| 未启用"反方" | 主 Agent **必须自己做一次自我反驳**并在报告里写明 |
| 用户自定义角色 | 目录注入行带**输出类型**（`摘要/状态/候选/反驳/通用`）与建议工具面；未知类型按"通用分析"处理 |
| 某环节失败/超时 | 沿用 C18 部分失败隔离：其余照常回流；主 Agent 用已有证据继续，并声明缺什么 |

## 四、不设轮次上限：影响与必须补的护栏（不违背"不设上限"）

去掉上限后可能出现"单专家长时间循环"（例如反复拉同一数据），因此补的是**可观测与可中止**，不是限额：

1. **无进展心跳**（已有 `agentProgressNotice`）：保留，并在 UI 显著位置显示"某专家已静默 N 分钟"。
2. **用户可取消**（已有）：取消必须能中断整条管线（含未启动环节）。
3. **成本可见**：运行详情必须显示**每位专家**的 token 与时长（现有分阶段记账 → 扩到专家级）。
4. **重复调用止损：董事会已决定不做**（保持不加约束）。此条仅作为已知风险保留：无上限且无重复止损时，单个专家理论上可能长时间重复取证，**兜底只有用户取消与无进展心跳**。
5. **诚实提示**：不设上限 + 串行管线在极端情况下可能跑很久（4 段 × 5 分钟 = 20 分钟）；缓解靠模型档位、并行安排与用户取消，而不是限额。

## 五、迁移（必须处理，因为用户已有配置）

**董事会决定（2026-09-19）：默认启用新 4 个角色；旧专家标记"已停用（历史角色）"、文件保留、默认不参与，用户随时可手动勾回。**

| 情形 | 处理 |
| --- | --- |
| 旧 8 个内置 | **不删文件**：内置表里标 `deprecated: true`（历史角色），默认启用集换成新 4 个；UI 分组显示"已停用（历史角色）"+ 可手动勾选 |
| Profile 曾经勾选旧 ID | 默认启用集 = 新 4 个；旧勾选保留在配置里但不生效（UI 明确提示"该专家已停用，可手动启用或改用新角色"），**不静默丢弃用户选择** |
| 用户改过旧内置文件 | 不覆盖、不迁移，按 C15 的 `modified` 规则照常显示 |
| 用户自定义的专家 | 完全不动 |
| 取消勾选某角色 | 按 §三 降级（主 Agent 自己承担该环节，并声明） |

## 七、实际使用中可能的问题清单（症状 → 影响 → 对策）

1. **忘了勾选数据专家** → 分析专家拿到空输入、凭空推理 → 降级：主 Agent 自己取证 + 声明；分析专家任务里强制要求"若无数据摘要，返回'证据不足'而不是猜测"
2. **自定义角色输出不是契约形态** → 主 Agent 不会用 → 目录带输出类型；未知按"通用分析"
3. **分析专家被当成决策者** → 责任错位 → 提示词明确"候选"；主 Agent 必须自写结论与理由
4. **反方走过场**（全盘同意/空洞反驳）→ 质量幻觉 → 要求逐条 + 可检验 + 允许"无法推翻"；记录 `contrarianResolutions[]`；复盘抽查
5. **串行环失败** → 全流程堵 → 部分失败隔离 + 明确缺什么 + 允许用旧摘要（须标时效）
6. **摘要时效过期**（分析用 5 分钟前的盘口）→ 结论基于陈旧数据 → 摘要逐条带时间戳与有效性窗口；主 Agent 决策前超阈值须重取或标注
7. **费用失控**（无上限 + 多段串行）→ 单轮 token 可能高于现在 → 专家级 token 可见；Profile 可给各角色选模型档位（摘要用便宜模型）
8. **并行争抢外部资源** → OKX 限频 → 并发上限 5 保留；数据摘要优先被引用，减少重复取证
9. **用户全勾选** → 回到"都点一遍" → 编排规则"按需要派"；UI 提示默认只启用 4 角色
10. **主 Agent 反复再来一轮反方** → 时间与 token 浪费 → 流程规则"反方最多一轮"
11. **试判与管线配合** → skip 不进管线；escalate 才进；名单为空 → 主 Agent 单干
12. **主 Agent 上下文被三份报告灌满** → 长上下文变慢变贵 → 输出契约要求紧凑 + 用证据 ID 引用而非复述
13. **审计缺失**（谁说了什么、如何裁决）→ 争议无法复盘 → 记录 `usedEvidence[]` / `contrarianResolutions[]` / 专家级 token 与时长
14. **旧配置引用已删专家** → 运行报错或静默不派 → 迁移映射 + UI 提示（§五）

## 八、已确认（2026-09-19 董事会）

1. **旧内置处置**：默认启用新 4 个角色；旧专家标"已停用（历史角色）"、文件保留、默认不参与、用户可手动勾回（旧勾选保留在配置里且 UI 明示，不静默丢弃）。
2. **重复调用止损：不做**。保持完全不加约束——不加"同一工具+同参连续 N 次"的警告；加上限之外的一切兜底都只有"用户取消"与"无进展心跳"。
3. **各角色模型档位：暂不做**。全部角色与主 Agent 同模型同档位；将来需要时再由 Profile 提供选型。
