## 1. 核心概念

| 概念 | 说明 |
| --- | --- |
| **Profile** | 一次自动化配置：模型、权限模式、绑定账户、关注品种、扫描间隔、Skill 集合与版本、唤醒条件、Agent 团队 |
| **运行（Run）** | Profile 被唤醒或手动触发后的一次完整执行：读证据 → 分析 → 决策 → 执行 → 保存摘要与下一组观察条件 |
| **唤醒条件** | 触发运行的条件，如定时、价格、成交量、盘口、订单、持仓、交易机会或市场情报事件 |
| **Skill** | 注入模型上下文的规则包（Markdown 规格），决定工具用法、交易哲学与证据解读 |
| **复盘（Review）** | 平仓后结合开仓前/持仓中/平仓后的市场路径，对决策、执行与结果分层评价 |

一次典型闭环：

```mermaid
flowchart LR
  Wake[唤醒条件命中] --> Run[Profile 运行]
  Run --> Evidence[读取行情 / 账户 / 情报证据]
  Evidence --> Decide[决策：机会 / 挂单 / 观察条件]
  Decide --> Execute[受限执行 + 审计]
  Execute --> Summarize[保存摘要与下一组观察条件]
  Summarize --> Review[平仓后生成仓位复盘]
  Review --> Improve[Skill 优化建议 → 用户确认 → 新版本]
```

## 2. 权限模式

Profile 的权限模式决定它**能做什么**，而不是提示词说什么：

| 模式 | 读市场与账户 | 交易机会 | 外部交易副作用 |
| --- | :---: | :---: | --- |
| `advisor` | 是 | 否 | 禁止 |
| `copilot` | 是 | 创建、修改、复用 | 必须由用户审批 |
| `limited_auto` | 是 | 通过冻结候选提交 | 仅限 Profile 授权范围 |

每一层校验依次经过：**Sidecar 工具可见性 → Agent runtime policy → Rust 账户与环境绑定 → 合约参数校验 → 交易预检 → 实盘确认 → 幂等控制 → 持久化审计**。

> [!WARNING]
> 自动化执行属于高风险能力。请从 `advisor` 与模拟盘开始，根据运行记录、对账与复盘逐步提升权限。实盘 Profile 的启用需要显式确认。

## 3. 创建第一个 Profile

导航到 **AI 自动化 → Profile**，点击新建：

1. **基础信息**
   - 名称：便于在运行记录与通知中识别。
   - 权限模式：建议从 `advisor` 开始。
   - 绑定账户与环境：模拟盘 / 实盘。
   - 关注品种：Profile 只在这些交易对上读写。
   - 扫描间隔：后台运行的节奏（分钟）。

2. **模型与推理深度**
   - 选择 Profile 使用的模型（与聊天助手独立）。
   - 推理深度影响证据链长度与耗时，可先用默认档位。

3. **Skill 选择**
   - 四个系统 Skill 始终强制加载（见第 5 节）。
   - 自定义 Skill 可以独立勾选；每个 Skill 固定到具体版本。

4. **Agent 团队**
   - 默认单 Agent；复杂任务可切换多 Agent 编排（见第 6 节）。

5. **唤醒条件**
   - 首次可以先不加条件，用"手动运行"验证一轮完整执行（见第 4 节）。

6. 保存并启用。Profile 状态、下一次唤醒时间与最近运行摘要会显示在列表中。

> [!TIP]
> 手动运行是验证 Profile 行为的最佳方式：修改 Skill 或唤醒条件后，先手动跑一轮确认摘要与决策符合预期，再放开自动唤醒。

## 4. 唤醒条件

Profile 的"观察计划"由一组**类型化唤醒条件**组成，每条条件都有明确的类型、参数与到期时间。

**条件类型**

| 类型 | 说明 | 示例 |
| --- | --- | --- |
| 定时 | 按间隔重复或指定时间 | 每 30 分钟；每天 08:00 |
| 价格 | 价格触及阈值 | BTC 突破 120,000 |
| 成交量 | 成交活跃度变化 | 1 分钟成交量超过均量 3 倍 |
| 盘口 | 挂单结构变化 | 买一档深度突增 |
| 订单 | 订单状态事件 | 限价单成交 / 撤销 |
| 持仓 | 仓位状态变化 | 仓位达到止盈目标 |
| 机会 | 交易机会状态变化 | 新机会进入审批 |
| 市场情报 | 情报事件 | Smart Money 信号变化 |

**组合与生命周期**

- 多条条件用 `任一命中（any）` 或 `全部命中（all）` 组合。
- 每条条件可设置**到期时间**，过期自动失效。
- 运行结束时，Agent 可以保存**下一组观察条件**（agent 来源），与用户手工创建的条件（user 来源）共同构成观察计划。

> [!NOTE]
> Agent 自己创建的唤醒条件同样受 Profile 账户与品种绑定约束：唤醒条件的账户必须与 Profile 绑定账户一致。

## 5. Skill 与版本快照

Skill 是注入模型上下文的**规则规格**。Profile 保存的是不可变版本快照——修改 Skill 不会改变历史运行所使用的规则。

**四个系统 Skill（始终加载）**

| Skill | 责任边界 |
| --- | --- |
| `desic-core-operations` | 工具、权限、交易机会、合约单位与执行规范 |
| `trading-philosophy` | 证据、市场状态、失效条件、风险与复盘原则 |
| `okx-market-intelligence` | 新闻、事件、情绪、宏观、Smart Money、OI、主动流、拥挤度、资金费率与基差 |
| `desic-trade-operations` | 交易机会、市场证据、永续风险、仓位生命周期、保护与执行核对 |

**自定义 Skill**（设置 → Skill 管理）

- 内置编辑 / 本地导入 / Git 仓库安装三种来源（Git 安装不要求本机安装 Git，见 [入门教程](./getting-started.md)）。
- 在 Profile 中按版本勾选；发布新版本后需要手动升级 Profile 中的快照，历史运行不受影响。

> [!TIP]
> Skill 是自动化行为的真正"策略层"。想调整自动化决策方式，改 Skill 而不是改提示词；改完先手动运行验证。

## 6. 多 Agent 编排

复杂任务可以组建专家团队。编排方案（Scheme）定义每个子 Agent 的角色、职责与只读范围：

- 典型专家：市场结构、情报资金、账户风险、反方审查（Devil's advocate）。
- 所有专家 **并行取证、只读**：不能创建机会、发送通知或执行交易。
- 唯一的主 Agent 汇总证据并承担最终决策。
- 反方否决必须附带**确定性预检结果**，防止空泛反对阻塞流程。

> [!NOTE]
> 多 Agent 会成倍增加模型调用与耗时。仅在对决策质量要求高、且单 Agent 证据链不足时使用；日常定时扫描用单 Agent 即可。

## 7. 运行记录与审计

**运行（Runs）** 列表记录每一次唤醒与手动运行：

| 字段 | 说明 |
| --- | --- |
| 状态 | 进行中 / 完成 / 失败 |
| 摘要 | 本轮决策与结论 |
| 动作统计 | 创建机会、挂单、通知等动作数量 |
| Token 用量 | 按运行统计，未报告的 usage 不会被伪装为零 |
| 下一次唤醒 | 观察计划中的最近一次触发时间 |
| 错误 | 失败原因（含诊断细节） |

运行中的会话可以直接打开查看完整消息、工具调用与审批记录。交易动作统一走终端的幂等执行与审计链路——与手动下单共用同一套对账机制。

## 8. 仓位复盘与优化建议

**仓位复盘**：完整平仓后，仓位被整理为 Position Episode，并结合开仓前、持仓中、平仓后的市场路径生成复盘。评价分三层：

| 层 | 评价对象 | 说明 |
| --- | --- | --- |
| 决策质量 | 开仓依据是否成立 | 规则与证据是否自洽 |
| 执行质量 | 成交、滑点、通知 | 与决策无关的操作问题 |
| 随机结果 | 单笔盈亏 | 不直接把盈亏解释为规则优劣 |

**优化建议**：只有证据指向可复用、可验证的 Skill 缺陷时才会提出：

1. 建议附带**采用前后的逐行差异**。
2. 用户确认后才发布为 Skill 新版本。
3. Profile 不会自动升级版本快照。

> [!NOTE]
> 复盘、机会与异常都可以推送到飞书（见下节），形成"运行 → 决策 → 复盘 → 迭代"的完整闭环。

---

## 9. 通知

在 **设置 → 通知** 配置飞书机器人后，以下事件可投递：

- Profile 运行摘要与异常
- 交易机会创建与审批请求
- 仓位复盘完成
- 优化建议发布

实盘相关通知建议全部开启；模拟盘验证阶段可以只开应用内通知。

## 10. 最佳实践

1. **从 advisor 开始**：先用只读 Profile 观察一段时间，检查它"看到了什么"和"如何推理"。
2. **模拟盘全流程验证**：数量单位、保证金、止损、通知与对账全部在模拟盘跑通后再开实盘。
3. **单一职责**：一个 Profile 专注一种模式（例如"BTC 突破监控"），比"全能 Profile"更易审计与复盘。
4. **唤醒条件设到期**：避免遗留条件在行情剧变时反复触发。
5. **Skill 变更走版本**：每次修改 Skill 发布新版本、写清变更动机，复盘才能归因。
6. **定期检查运行记录**：失败的运行要读错误与摘要，而不是只看完成数。

## 11. 常见问题

**Q：Profile 会自动升级 Skill 吗？**
不会。Profile 冻结版本快照；你需要手动升级，历史运行使用的规则保持不变。

**Q：Agent 能自己加唤醒条件吗？**
运行结束时 Agent 可以保存下一组观察条件，但同样受账户与品种绑定、到期时间约束；你随时可以删除。

**Q：多 Agent 会增加多少成本？**
每次运行会为每个专家调用模型。建议按需启用，定期评估专家数量是否与决策质量收益匹配。

**Q：为什么我的实盘 Profile 无法启用？**
实盘启用需要：绑定账户的读取与交易权限、与本账户其他自动化/策略 Profile 的冲突审查、以及显式确认。检查运行列表中的错误提示。
