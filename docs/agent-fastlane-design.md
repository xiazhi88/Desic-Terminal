> 状态：**草案，待董事会确认 §13 待确认项后冻结为契约 C29**
> **C29 快判模式：实现完成、本版本未开放（`FASTLANE_MODE_ENABLED=false`），下个版本开放。**
> 本版本只做"开关 + 入口隐藏"（代码一行未删）：开关点与撤下范围见 `docs/pending.md` §C29.19。
> 依据：本文件所有耗时/成本数字均来自 2026-09-20 的真实离线探针（`scripts/experiments/fastlane-shadow-probe.mjs`，产物 `artifacts/fastlane-probe/*.json`）

## 0. 一句话定义

**快判模式**：用"**代码取数 → Jev 秒级判定 → LLM 写参数/写下一轮观察条件 → 代码校验执行**"的闭环，替代现有"LLM 从零分析整轮"的慢循环；每轮只在**两次模型调用**内完成（目标 P50 ≤ 3 秒），并**复用现有 Profile 的触发机制（观察条件 + 最长静默）**形成闭环。

## 1. 与现有模式的关系

**复用**（不新造）：
- 触发：**观察条件（`nextWakePlan`，19 类）** + **最长静默兜底** + 手动触发；由既有 worker 循环评估（实测节拍 **2–5 秒**）；
- 限额：最小触发间隔、每小时最多运行（现有默认 60s / 12 次，快判模式另给默认值）；
- 执行：**顾问 / 副驾驶 / 自动执行（受限）** 三种执行模式；
- 动作工具：**创建机会**（`trade_opportunities` 链路）与既有下单/风控链路（precheck、租约、执行尝试记录）；
- 记录：运行记录 + 观察条件表（`ai_wake_conditions`）。

**新增**：
- 新 Profile 类型（快判模式）与**独立配置窗口**；
- 每轮的 **Jev 判定**（TypeSafe `POST /v1/systemone`）；
- **窄调用 LLM**（一次性、无工具、关思考）负责写参数与写下一轮观察条件；
- 独立的运行记录视图（分段耗时、判定概率、观望原因）。

**明确不做**：❌ 升级（escalate）概念 ❌ 影子模式 ❌ 剧本/卡片实体 ❌ `need_llm` 问题。
不确定 → **一律观望**，并由 LLM **创建下一轮观察条件**，等条件命中再进来。

## 2. 触发与闭环

```
        ┌────────────────────────────────────────────────────────┐
        │  观察条件命中 / 最长静默到期 / 手动触发                  │
        └──────────────────────┬─────────────────────────────────┘
                               ▼
   ① 代码取数（实时快照，目标 <300ms）
   ② 代码门：数据达标？异常？多周期冲突？  ── 不达标 ──▶ 观望（reason=data/anomaly/conflict）
   ③ Jev 判定（0.7–0.8s）：`long_score` / `short_score` + quality（变更 B：不再选动作标签）
        ├─ **代码**判：max(两分) < 门槛 / 两分并列 → 观望（含"置信度低/质量低"）──▶ ④
        └─ **代码**判：max(两分) ≥ 门槛且不并列 → 方向 = argmax（= 开多/开空）──▶ ⑤
           （**降险动作由停机平仓轮触发，同样经 LLM 写参数，不走旁路**）
   ④/⑤ LLM 窄调用（0.6–1.2s，关思考）：
        · 观望分支：只写「下一轮观察条件」+ 一句话结论
        · 动作分支：写参数（含开仓与降险两类）→ 调用「创建机会」/风控动作工具 → 同样写「下一轮观察条件」
   ⑥ 记录：分段耗时、判定概率、校验结果、动作/观望原因
                               │
                               └──▶ 回到「观察条件 / 最长静默」等待下一轮
```

**闭环关键**：无论 Jev 判"观望"还是"交易"，**每轮都由 LLM 产出下一轮观察条件**（复用现有 `nextWakePlan` 机制），因此不存在"睡死"的情况；再有 **最长静默** 做兜底。

**触发节拍**：不再依赖"定时扫描"（分钟级太慢）。快判模式的观察条件由既有 worker 循环评估（2–5 秒一次），配合更短的最小触发间隔（见 §9 默认值）。

## 3. 单轮时序预算（实测依据）

| 段 | 目标 | 实测（2026-09-20） |
| --- | --- | --- |
| 取数（实时读，内存快照） | < 300ms | 1,314–1,475ms（**离线探针从数据库读 + sqlite 子进程**；应用内实时读可大幅下降） |
| 代码门（数据/异常/冲突） | < 20ms | 1–2ms |
| **Jev 判定** | < 1s | **705–779ms**（5 次样本；`jev-1.13.0`） |
| **LLM 窄调用** | 0.6–1.5s | **538–1,187ms**（关思考；`deepseek-v4-flash`） |
| 代码校验 + precheck + 下单 | < 500ms | 未实现（复用既有链路） |
| **全链路** | **≤ 3s（P50）** | **2,591–3,111ms**（不含下单） |

**必须遵守的三条实测结论**：
1. **参数调用必须关思考**（`reasoning_effort: "none"`）：关掉 0.6–1.1s；开启时 8.1s 且 1,500/1,500 token 全被思考吃光、输出为空（`finish_reason=length`）。
2. **取数必须走实时路径**：落盘表的滞后为 已收盘 K 线 0–60s、衍生品 0–5 分钟、账户快照（仅在运行时写）可达数小时；实时读路径（ticker/盘口/账户）为毫秒–百毫秒级。
3. **多周期需自行聚合**：库中只有 `1m`/`1H`/`1Dutc`，5m/15m/4H 由 1m 聚合（探针已实现）。

## 5. Jev 的问题（2–3 个，全部事实绑定）

> **2026-09-21 变更 B（用户裁决：实验结论改生产）**：删掉 `action`（choice，含"观望"），换成两个
> `score`；方向由**代码**按门槛判（`max(long, short) ≥ 门槛` 且不并列 → argmax；否则观望）。
> 依据 `artifacts/fastlane-jev-rephrase-probe/report-20260921-070600.md`：同一份 byte 级相同的 state，
> 含"观望"的选择题**给方向率 0.0%**，换双打分后阈值 1.0 给 80.5%、1.5 给 16.0% ——「观望」是
> **选项结构造成的标签偏差**，不是它没有方向偏好。实现：`scripts/cline-fastlane.mjs::buildJevQuestions`
> / `decideEntryFromScores` / `normalizeJevVerdict`（旧形状 `action` 响应仍按原路径解析，向后兼容）。

| question id | type | 内容 | 备注 |
| --- | --- | --- | --- |
| `long_score` | **score** | 就在此刻、对这个 state 里的 `<品种>`，**做多这一个具体动作**有多该做？（0–4 档锚点逐档给出；问的是"现在做多该不该做"，不是"这个品种好不好"） | 返回 `score + probabilities + confidence`；⚠️ `score` 是 **0–4 分布上的期望值**（实测集中 0.2–1.9），不是档位 |
| `short_score` | **score** | 同上，问"现在**做空**这一个具体动作" | 与 `long_score` 一起交给代码判方向（入场门槛 `fastlane_entry_score_floor`，默认 1.5，clamp 0.5–3.0） |
| `reduce_score` | **score** | 就在此刻、对这个 state 里的 `<品种>`，**减仓/平仓（降低风险）这一个具体动作**有多该做？（0–4 档锚点逐档给出；问的是"现在针对 `state.account.positions` 里的**现存持仓**该不该降险"，**没有持仓时给 0**） | **C29.14 新增**（修 C29.13 的能力回退）：`reduce_score ≥ 降险门槛` → 代码判**降险**（**优先于开仓**，走 C29.10 那条已验证链路）；没有可减仓位（无持仓 / 持仓事实缺失）→ 观望并留痕（两个码分层文案）。**永不映射成开仓**。降险门槛 `fastlane_reduce_score_floor`（**C29.17 起独立**，默认 1.5，clamp 0.5–3.0）。这一问换问法实验**没测过**，证据只在 `artifacts/fastlane-reduce-score/` |
| ~~`quality`~~ | ~~score~~ | **C29.18 删除**：换问法实验证明它对「该不该做」没有可用判别力（门槛 1.2 落在它自己的支撑集之外 = 等于没拦；三种换问法 AUC 全部低于现状）→ 入场质量改由**纯代码判据**承担（结构可辨 / 止损可放 / 几何 R:R 达线，三条各有独立原因码）。老侧车/老记录带 `quality` 只作**观察量**留痕。 | — |
| `setup_valid`（可选） | **noul** | 这次入场在语义上算不算到位（回踩到位、非追高、结构健康）？ | 只留模型才能答的语义判断 |

**降险信号（C29.14 已恢复）**：变更 B 曾把"减仓/平仓"从问题面删掉 → Jev 无法自判降险（22 条历史降险样本 21/22 → 0/22，
用户裁决「降险不能被拦、不能走旁路」）→ C29.14 用 `reduce_score`（仍是打分风格）恢复该能力。降险有两类触发路径：
① **Jev 判降险**（`reduce_score ≥ 降险门槛` 且有可减仓位；记录 `intent="reduce"`）；② **停机平仓轮**（用户显式命令，
`fastlaneIntent="close"`，跳过 Jev）。两条都走 C29.10 的豁免链路（质量门/置信度门只作用于开新仓），
参数仍经 `validate_round` 与预检，**无旁路**。

**两条门槛解耦（C29.17，2026-09-21）**：入场门槛 `fastlane_entry_score_floor`（默认 1.5）与降险门槛
`fastlane_reduce_score_floor`（默认 **1.5**，**C29.17 起独立字段**）各自独立可调，clamp 同规则 0.5–3.0。
**默认值同值 ⇒ 与 C29.14"复用同一门槛"逐字一致**（本轮不改行为，只把旋钮交出来）。记录里分别落
`entryScoreFloor` / `reduceScoreFloor`（**不再强制相等**）。
理由：两类动作取向不同 —— **开仓要挑**（宁缺毋滥；放宽的代价是新仓位与新暴露），**降险要快**
（宁可多减一点；多减的代价是少赚）。且降险**只作用于既有持仓**（持仓事实不是 `held` 时一律不动手）
→ 放宽降险不会产生新仓位、不放大暴露。**先把降险放宽**（例如降到 1.0），开仓门槛保持不动。

**无 `need_llm`**。升级判据全部下沉到代码（§8）。

## 6. LLM 的两项职责（每轮各一次窄调用）

### 6.1 分支 A：Jev 判"观望"

```
系统：你是 Desic 快判模式的「观察条件编译器」。只输出一个 JSON 对象；不要解释、不要 markdown、不要调用工具。
输入：state（含字段时间戳）+ Jev 结论（action/probabilities/quality）+ 当前观察条件清单 + 限额
输出：
{"summary":"<一句话结论，≤160 显示宽度>",
 "nextWakePlan":{"mode":"any|all","conditions":[{"type":"price_cross|price_band|timer|position_changed|order_state_changed|volatility_shift|funding_extreme|radar_alert|...","params":{...}}],"expiresAtMs":<ms>},
 "reason":"data|anomaly|conflict|low_confidence|low_quality|no_setup"}
```
- 条件数量与窗口受既有 `validate_wake_condition_limits` 约束（复用）；
- 条件必须**可被 2–5 秒节拍的 watcher 评估**（优先 `price_cross` / `price_band` / `timer`）。

### 6.2 分支 B：Jev 判"开多/开空"

同上，但先写参数、再调用**创建机会**工具，两份产物都进同一次调用：

```
输出：
{"opportunity":{…创建机会所需的参数…},
 "order":{"side":"long|short","order_type":"limit|market","entry_px":…,"stop_px":…,"tp":[…],
          "size":{"contracts":…,"risk_pct":…},"leverage":…,"margin_mode":"cross",
          "invalidation":[…],"reason_tags":[…],"confidence":…},
 "nextWakePlan":{…与 6.1 同结构…},
 "summary":"<一句话>"}
```
**参数写完后仍由代码校验（§8.1）**；不合格 → 当轮不创建机会，改为观望并写观察条件。

### 6.3 prompt 纪律（已实测有效）

- **必须关思考**（`reasoning_effort: "none"`；开思考时 8.1s、输出为空）；
- 一次性、无工具、`max_tokens ≈ 800`、`temperature ≈ 0.2`；
- 输入里所有事实带时间戳**且互相自洽**：实测中模型会主动发现"账户年龄与时间戳冲突"并拒绝输出 —— 这是好事，但要求 state 必须自洽；
- **硬约束要给"可实现口径"**：例如止损写"`max(最近结构位, entry − 1.5×ATR14_1h)`"，而不是"放在 4H 整窗之外"（后者实测被模型正确拒绝，因为无法同时满足盈亏比与风险上限）。

## 7. 执行模式（复用现有三种）

| 执行模式 | 快判模式下行为 |
| --- | --- |
| **顾问** | LLM 创建机会 → 结束（由人决定是否交易） |
| **副驾驶** | LLM 创建机会 → **审批通过后**自动交易（复用既有审批链路） |
| **自动执行（受限）** | LLM 创建机会 → **自动交易**（受 §8 限额约束） |

**降险动作**（减仓 / 平仓 / 收紧止损 / 撤销挂单）：**与开仓动作同一条链路** —— Jev 判定 → **LLM 生成参数** → 代码校验 → 按执行模式落地（顾问=只出结论/机会，副驾驶=审批后执行，受限自动=自动执行）。
> **已知代价（董事会 2026-09-20 明确接受，无旁路）**：在"顾问/副驾驶"模式下，降险动作的落地需要人工或审批，**存在延迟**；若将来需要"紧急降险例外"（例如触达止损或强平风险时由代码直接执行），需另行裁决并写入契约。

**观察量与挂单的关系**：每轮创建的机会若未成交，按既有逻辑进入挂单；下一轮观察条件里应包含 `order_state_changed`（已有类型）。

## 8. 安全与限额

### 8.1 代码校验（LLM 之后必须再过一遍）

1. 止损必须在失效位之外（做多：`stop < 结构位`；做空反之）
2. 单笔风险 ≤ `单笔风险%`；保证金 ≤ Profile 上限
3. 盈亏比 ≥ 风格里设定的底线（默认 1.5）
4. 手数 ≥ 最小手数且 ≤ 上限；杠杆 ≤ 上限；保证金模式合规
5. 入场价在合理区间（或市价时滑点 ≤ 上限）
6. 数据新鲜度达标（§4 `data_age_ms`）
7. 时段/事件黑名单通过

任一条不满足 → **当轮不创建机会**，改为观望（`reason=validation_failed`）。

### 8.2 频率与预算

| 限制 | 建议默认（快判模式） |
| --- | --- |
| 最小触发间隔 | **10 秒**（现有 Profile 默认 60 秒） |
| 每小时最多运行 | **120 次**（现有默认 12 次） |
| Jev 调用上限 | 与运行上限同源（每次运行 1 次 Jev） |
| 最长静默兜底 | **10 分钟**（现有默认 30 分钟） |
| 动作频率上限 | 每分钟 ≤1、每小时 ≤5 |
| 单日最大亏损 | 默认 2%（触达即停机） |
| 一键停机 | 立即停止判定；可选平掉快车道仓位 |

超出运行/预算上限 → 当轮**不判定**，在记录里写明 `budget_exhausted`。

## 9. UI：新建 Profile 的两张卡片 + 独立配置窗口

### 9.1 新建 Profile 卡片（2 张，美观且各两三句话讲原理）

| 卡片 | 标题 | 副标题 | 原理要点（卡片上的 3 条） | 适合 |

## 10. 运行记录适配（新模式）

运行记录新增/调整字段（沿用现有钩子风格）：

| 分组 | 内容 | 钩子 |
| --- | --- | --- |

## 12. 明确不做

- ❌ 升级 / escalate：不确定就观望，由 LLM 写下一轮观察条件；
- ❌ 影子模式：直接以"顾问"起步（最保守的执行模式）；
- ❌ 剧本 / 卡片实体；
- ❌ 降险动作旁路（不跳过 LLM/审批：降险与开仓走同一条链路）；
- ❌ `need_llm` 问题；升级判据全部下沉代码；
- ❌ 复用 AI Profile 的配置界面（快判模式独立重做）。
